# Pico implementation outcomes

- [ ] **Cambridge grammar and statements:** Implement the Cambridge Computer Science pseudocode forms in the attached `UnsolvedCopyofIGCSE_Programming_Student_Booklet.docx`; support `DECLARE name, name : TYPE`, constants, assignments, typed `INPUT`, `OUTPUT`, comments, operators, nested `IF`/`ELSE`/`ENDIF`, and Cambridge `THEN` on its own following line as well as the same-line form; implement `CASE OF` branches, `OTHERWISE`, `ENDCASE`; implement inclusive `FOR`/`TO`/optional `STEP`/`NEXT`, `WHILE … DO`/`ENDWHILE`, and `REPEAT … UNTIL`; do not invent a new programming language or syntax.
- [ ] **Booklet library and text routines:** Implement `LENGTH`, `SUBSTRING(Text, Start, Length)` using the booklet's one-based string positions, `UCASE`, `LCASE`, `DIV`, `MOD`, `ROUND(Value, Places)`, and `RANDOM()`; retain any existing compiler-provided routine aliases only as compatibility support; keep completion, hover documentation, helpful errors, token/AST views, coverage, debugger and flowcharts synchronized with Cambridge forms.
- [ ] **User-defined procedures, functions and scope:** Implement typed `PROCEDURE` definitions and `CALL` with zero to three parameters; implement typed `FUNCTION … RETURNS … ENDFUNCTION`, expression calls and `RETURN`; support local variables, parameters, globals and local/global shadowing as shown in the booklet.
- [ ] **One- and two-dimensional arrays:** Support declarations such as `DECLARE Marks : ARRAY[1:5] OF INTEGER` and `DECLARE Grid : ARRAY[1:2,1:3] OF INTEGER`; support the booklet's zero/one-based bounds, variable indexes, element input/read/write/assignment, and traversal by nested iteration.
- [ ] **Booklet file handling in a client-only workspace:** Implement `OPENFILE "…" FOR READ|WRITE`, `READFILE`, `WRITEFILE`, and `CLOSEFILE` for text items/lines with spaces preserved and writes in the selected mode; store practice files in a clearly labeled browser-local virtual filesystem instead of assuming unrestricted access to the user's computer.
- [ ] **Editor learning tools and Auto-declare:** Keep the pseudocode editor with line numbers and syntax highlighting; retain the Autocomplete, Autocorrect with “Did you mean?” suggestions, and Hover Documentation toggles; add a remembered Auto-declare setting with a configurable default type and a visible explanation of inserted valid declarations; add a Cambridge-only Syntax cheat sheet; convert typed `<--` to `←` in the editor.
- [ ] **Run, debug, test and visualise the complete syntax:** Keep a Run button and output console; keep helpful error messages; support Visual Debugger step-by-step execution, current line and variables; support Flowchart, Test Cases with expected versus actual output, Code Coverage showing executed lines, and AST and Token viewers; add Cambridge booklet examples; Projects save automatically; Settings remember the user's preferences; preserve the core workflow “Write → Run → Debug → Test → Visualise → Learn”.
- [ ] **Customizable and persistent IDE layout:** Let the user change field/panel sizes, move or rearrange panels, choose whether the project sidebar is left or right and whether tools are docked bottom or right, reorder dock panels, and choose Standard Input's position; persist layout choices in the user's browser, provide a reset-to-default option, and keep the controls usable on mobile. Keep the UI clean, dark, modern and beginner-friendly.
- [ ] **Project File menu and editor shortcuts:** Add a File menu at the top-right to import or export `.pico` project files; support Ctrl+F search, Ctrl+H replace, and Ctrl+S save, with platform-appropriate Command shortcuts where applicable and clear saved feedback.
- [ ] **Requested footer attribution:** Display this footer text: “Deployed by MUSTAQIM 11 Boys Red and made by AMAR 11 Boys Blue”.
